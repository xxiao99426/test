# 演示视频分镜

题目要求两段 3～5 分钟视频，至少展示 6 个场景。下面按「一段拍什么」拆成两个独立视频，每个 3 分半左右。

**拍摄前务必做完的准备工作**（否则会重拍）：

1. 三个进程全部启动：`cd server && go run .`、`cd web && npm run dev`、Unity 打开 `Assets/Scenes/Inspection.unity`
2. 清空演示数据，保证从零开始：停掉 Go → 删除 `server/data/problems.json` → 重启 Go
3. Unity 进 Play，确认右上角显示「场景内问题 0 条」
4. 浏览器开好 `http://127.0.0.1:5173`，**放在旁边不要切走**（后面要来回切）
5. 录屏工具开 1080p、30fps，鼠标指针高亮打开（观众要看得见你点了哪里）
6. 窗口都调到 1600×900 左右，别用全屏——评审要同时看到窗口边界
7. 麦克风试一句，环境安静

> 关键要求：**操作放慢**。点击前停 0.5 秒，鼠标移动不要甩，让观众看清「点的是哪个面、标记落在哪」。

## 视频一：Unity 端巡检上报（约 3 分 30 秒）

主题：在现场走一圈、发现一处异常、点上去、填表、提交成功。

### 0:00–0:20 开场（口播）

> 「这是一个工业巡检 Demo，Unity 做现场端，Go 做后端，React 做管理端。这一段的流程是：在虚拟厂房里走一圈，发现问题，点一下设备，把问题上报上去。」

画面：Unity 窗口 + Game 视图，展示有 0 个标记的空场景，右上角「场景内问题 0 条」。

### 0:20–1:10 场景漫游（对应要求①「移动、观察虚拟现场」）

- 按 `W` 往前走 2 秒，按 `A` 绕到机柜左侧
- **按住鼠标右键**左右拖动，展示转视角（口播提醒：「转视角要用右键，左键留给放置标记」）
- 走到两台机柜之间，抬头看顶部管线桥架
- 走到墙边，故意往墙上撞一下，说明有碰撞不会穿墙

口播要点：
> 「场景是脚本生成的，地面、墙、四台机柜、顶部管线都在，全部带碰撞体。移动用 CharacterController，所以不会穿墙。」

### 1:10–1:50 放置标记（对应要求②「点击设备或场景表面并放置标记」）

- 鼠标移到 **1 号机柜右侧面板的上边缘**（不要点正中间！）
- 停顿 1 秒，让观众看清鼠标位置
- 点击 → 标记出现，表单同时弹出

口播要点（这一段是评分重点，一定要讲）：
> 「注意标记的**杆底**就贴在我点的这个位置，不是放在物体中心。代码里用的是射线命中点 `hit.point`，不是碰撞体中心 `bounds.center`。杆沿着表面法线伸出来，球头浮在表面外。」

- 再点一下机柜**正中间**，说明标记会移动过去而不是多出一个
> 「同一个待提交状态只允许一个标记，再点一次是移动，不是新建。」

### 1:50–2:30 填写并提交（对应要求③「填写并提交问题」）

- 标题输入「1 号机柜右侧温度偏高」
- 描述输入「用手背靠近能感觉到明显热风，疑似散热风扇故障」
- 优先级点「高」→ 按钮变红
- 指出表单里的坐标行：「这就是点提交时会上报的坐标，和标记位置同源」
- 点「提交」→ 绿色提示条「上报成功：「…」已保存到后端」→ 标记从青绿脉动变成红色

口播：
> 「提交走的是 Go 的 POST 接口，成功后标记从「待提交」青色变成已保存的红色——按优先级上色。」

### 2:30–3:10 演示 UI 不穿透 + 取消不残留（这一条评审会看）

- 在**输入框上**快速点 5 下（边点边数），回到 Game 视图：「场景里没有多出任何标记」
- 再点一次地面 → 标记出现 → 点「取消」
- 口播：「取消之后标记立刻从场景消失，不会留一个点不到又看得见的幽灵标记。」

### 3:10–3:30 收尾

- 展示右上角「场景内问题 1 条」
> 「这一条已经在后端了，下一段去管理端看。」

## 视频二：管理端与后端持久化（约 3 分 30 秒）

主题：React 看到同一条数据 → 改状态 → 停掉后端看提示 → 重启后端数据还在 → 回 Unity 看颜色变了。

### 0:00–0:20 开场

> 「这一段的重点是三端用的是同一份数据，以及后端重启后数据不丢。」

### 0:20–1:00 React 看到 Unity 上报的问题（对应要求④）

- 切到浏览器（**刷新页面**，不要靠已有缓存）
- 口头对照：「标题、优先级高、状态待处理、坐标 `(-4.47, 1.20, 5.45)`，和刚才 Unity 里标记的坐标一样」
- 鼠标停在坐标列上，展示和 Unity 表单里的一致

口播：
> 「这是 Unity 写进 Go 的那一条。管理端没有任何本地数据，全是接口拉回来的。」

### 1:00–1:40 React 修改状态（对应要求⑤）

- 下拉从「待处理」改成「处理中」→ 绿色提示条出现
- **按 F5 整页刷新**，证明不是只改了界面
- 再改成「已解决」，再刷新一次
- 口播：「每次改完都刷新一次，状态还在，说明写进了后端，不是内存里改的。」

### 1:40–2:20 后端不可用（必做项：异常要有处理）

- 切到终端，`Ctrl+C` 停掉 Go（或 `taskkill /F /IM server.exe`）
- 回浏览器刷新 → 红色错误条 +「重试」按钮，**页面没有白屏**
- 口播：「后端挂了，页面不会白屏，会明确告诉我连不上，并且给我一个重试按钮。」
- 顺手回 Unity 提交一次，展示红色错误提示 + 标记和已填内容都还在
  > 「Unity 这边也一样，失败会保留草稿，后端恢复后直接点提交就能重试。」

### 2:20–3:00 **Go 重启后数据仍在**（对应要求⑥，关键证据）

- 重新启动 Go：`cd server && go run .`
- 日志出现在终端：`[BOOT] 数据文件 data/problems.json，已加载 N 条问题`
- 浏览器点「重试」→ 列表回来，**之前那条仍在，状态仍是「已解决」**
- 打开一次 `server/data/problems.json`（编辑器里滚一下），指出记录确实在文件里
- 口播：「数据存在 JSON 文件里，写盘用临时文件加原子重命名，进程被强杀也不会写坏。」

### 3:00–3:30 回 Unity 验证颜色跟随状态

- 切回 Unity，**Stop 再 Play**（重新恢复标记）
- 指向那个标记：「刚才在 React 里把它改成了已解决，现在恢复出来的标记是绿色——状态优先于优先级配色。」
- 再展示右上角「场景内问题 N 条」

### 3:30 收尾

> 「这一段证明的是三端闭环：Unity 写、Go 存、React 改，改完 Unity 重新加载能看到变化。」

## 拍完之后自检清单

对着录好的视频逐条确认，缺任何一条都要补拍：

- [ ] 能看到虚拟现场，并且**移动过**（不是静止画面）
- [ ] 能看到**转视角**
- [ ] 点击设备表面后，标记出现在**点击的位置**（不是物体中心）
- [ ] 表单里填了中文标题和描述，选了优先级
- [ ] 提交后有**成功提示**
- [ ] React **刷新后**能看到那条问题，且坐标与 Unity 一致
- [ ] React 改了状态，**刷新后仍然是新状态**
- [ ] 停掉后端后，React 和 Unity 都有**明确的错误提示**（不白屏、不静默失败）
- [ ] **Go 重启后数据仍在**
- [ ] 回 Unity 能看到标记颜色随状态变化
- [ ] 视频时长在 3～5 分钟之间，声音清楚

## 常见补拍原因

| 现象 | 原因 | 处理 |
|---|---|---|
| 提交报「无法连接后端」 | 没启动 Go | 启动后点「提交」重试即可，不用重录 |
| React 列表是空的 | 清过数据文件 | 重新在 Unity 提交一条 |
| 标记钻进机柜看不见 | 恢复了旧的贴墙标记（朝向问题） | 属于已知问题，重新放一个新标记演示 |
| 中文显示成方块 | 字体文件缺失 | 确认 `Assets/Fonts/SimHei.ttf` 存在 |
